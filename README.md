# CookieMarkets
[![CI](https://github.com/DrEsmaily/cookie-markets/actions/workflows/ci.yml/badge.svg)](https://github.com/DrEsmaily/cookie-markets/actions/workflows/ci.yml)

Where Predictions Become Markets
CookieMarkets is an on-chain prediction-market protocol and consumer application built for Cookie Chain. Anyone can launch a clearly defined market, provide its initial COOK liquidity, and earn that market's liquidity-provider fees. Traders take simple YES or NO positions and can profit when their prediction is correct. Market creation, trading, custody, settlement, refunds, and claims are enforced by the deployed program rather than by a hidden application balance.#### [Open the live Cookie.Markets](https://cookie.markets)

The first live market template focuses on BTC and ETH price outcomes because they are familiar, liquid, and objectively verifiable. The protocol is designed to grow beyond crypto into ecosystem milestones, governance, community forecasts, creator markets, sports, culture, and other events with explicit resolution rules.

## Why it matters

CookieMarkets gives COOK a repeatable role in a real consumer product:

- **Creators become liquidity providers.** A creator supplies a market's initial liquidity and can earn the LP fee generated by that specific market.
- **Traders can earn from informed predictions.** A winning share is redeemable for the settlement value defined by the protocol.
- **COOK gains productive utility.** COOK is used for liquidity, trades, claims, and fees instead of only being held or transferred.
- **Liquidity remains visibly committed.** Every live market begins with meaningful collateral locked under program control.
- **Activity returns to Cookie Chain.** Creation, trading, resolution, claims, and account cleanup create transparent on-chain activity.
- **The platform has configurable revenue.** A separate platform-owner fee and recipient are stored in the on-chain protocol configuration.

These mechanisms can increase network activity and token utility, but they do not guarantee adoption, revenue, token appreciation, or investment returns.

## Live product experience

### Create a market

1. Choose BTC or ETH and an **above** or **under** price condition.
2. Set the USD threshold and exact UTC settlement time.
3. Choose the starting YES/NO balance and supply at least 100 COOK of liquidity.
4. Review the generated question, Coinbase settlement method, and fee policy.
5. Approve the transaction in Nightly.

The creator is the liquidity provider for that market. The market's LP fees belong to that creator and are released through final settlement when the result is valid.

### Trade YES or NO

The interface shows the current odds, maximum permitted trade, fee breakdown, total payment, current position, and potential winning payout. Each purchase is capped at 1% of current pool liquidity so the pool can recalculate between trades and limit abrupt price movement.

Trade quotes use the current on-chain `ProtocolConfig` and separate base cost, liquidity-provider fee, platform-owner fee, total fee, final payment, and potential payout. The frontend does not duplicate fee percentages as business constants; authorized on-chain updates are reflected in subsequent quotes.

### Resolve and claim

Supported price markets commit to Coinbase Exchange's exact preceding one-minute candle close. The resolver worker locks expired markets, collects the committed evidence, and submits the result. A valid YES or NO result enables winning-share and creator settlement claims.

If evidence cannot be verified, the market can finalize as **Invalid**. Invalid markets do not use the normal winner payout and do not distribute accrued LP or platform fees. Each trader instead receives the collateral cost basis tracked for that position. This deterministic accounting supports buyers who entered at different prices and prevents aggregate refunds from exceeding the market vault.

Native COOK is wrapped only when token-program compatibility requires it. User flows unwrap returned collateral and close eligible temporary or spent token accounts so the wallet receives normal native COOK and recoverable account rent.

## Protocol economics and control

`ProtocolConfig` stores the current admin, resolver, approved collateral mint, `liquidity_provider_fee_bps`, `owner_fee_bps`, `owner_fee_recipient`, and challenge period. Only the current admin can update this configuration. The same instruction can transfer administration to a new public key, allowing protocol control and revenue settings to move to a new owner or governance system without hard-coded frontend changes.

The LP recipient is **not global**. Every AMM pool records its own market creator, and that market's LP fee accrues for that creator. Platform-owner fees accrue separately for the configured protocol recipient. Both are held until valid settlement; an Invalid result preserves trader refund liabilities instead.

## Run locally

Requirements: Node.js 22 or newer, npm, and Nightly configured for Cookie Chain.

```bash
git clone https://github.com/DrEsmaily/cookie-markets.git
cd cookie-markets
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Deploy with Docker

On Ubuntu or Debian, the installer adds Docker when needed, clones the repository, builds the application, and exposes it on `127.0.0.1:3100` for an HTTPS reverse proxy:

```bash
curl -fsSL https://raw.githubusercontent.com/DrEsmaily/cookie-markets/main/deploy/install.sh | sudo bash
```

Use another local port with:

```bash
curl -fsSL https://raw.githubusercontent.com/DrEsmaily/cookie-markets/main/deploy/install.sh | sudo COOKIE_MARKETS_PORT=3200 bash
```

Published terms and evidence live in a persistent Docker volume. The public installer intentionally does not start the resolver because the resolver wallet must be mounted securely and read-only. Never bake a keypair into an image or commit it to the repository.

## Architecture

- `app/` — Next.js pages and server routes.
- `components/` — market, wallet, trading, creation, claim, and status interfaces.
- `lib/` — strict account decoding, instruction construction, AMM quotes, terms, evidence, and transaction preparation.
- `programs/cookie_markets/` — the Anchor/Rust program deployed on Cookie Chain.
- `scripts/market-keeper.mjs` — automatic locking and price-market resolution worker.
- `tests/` — client, arithmetic, HTTP, transaction, and disposable-validator integration tests.
- `deploy/` — isolated Docker/VPS installation and service configuration.
- `docs/` — protocol, market terms, operations, and historical design notes.

## Current scope and roadmap

The deployed MVP supports real COOK collateral, creator-funded AMM markets, on-chain configurable fee splitting, exact cost-basis Invalid refunds, automatic Coinbase price settlement, wallet positions, claims, native-COOK cleanup, and responsive desktop/mobile interfaces.

Near-term priorities include independent security review, redundant resolver operation, production monitoring, evidence backups, richer portfolio reporting, accessibility QA, better discovery, and multisig governance. Longer-term opportunities include more assets and data sources, Cookie Chain ecosystem and governance markets, creator liquidity tools, deeper secondary-market liquidity, public APIs, embeddable markets, and decentralized resolution designs.

## Security notice

The product uses a real deployed program and real COOK, but it has not received an independent external security audit. Use limited amounts while the protocol accumulates production history. No private key, seed phrase, wallet export, funded credential, or resolver secret belongs in this repository, an issue, a pull request, or a support message.
